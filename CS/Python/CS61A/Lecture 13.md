# 2. Abstraction Barriers 抽象屏障

### 核心定义
**抽象屏障**是一种编程设计思想，它在程序的各个部分之间划定界限。其核心目标是：**让程序的每一层都只需要关注“做什么”，而不需要关心下一层“是怎么做的”。** 
### 为什么要这样做
1. **易于维护 (Maintainability)：** 修改底层存储方式（如从 `list` 换成 `dict` 或 `tuple`）时，高层代码无需任何改动。
2. **降低复杂度 (Complexity Management)：** 开发顶层功能时，大脑不需要负担底层数据结构的实现细节。
3. **团队协作 (Collaboration)：** 不同的开发者可以分别负责不同层级的开发，只要沟通好层级间的接口（API）即可。
### 三层结构分析（以有理数 `Rational` 为例）

| **层级**     | **处理内容**   | **将数据视为...**                          | **使用的工具 (API)**                                  |
| ---------- | ---------- | ------------------------------------- | ------------------------------------------------ |
| **顶层：使用层** | 执行具体的业务计算  | **整体数值** (Whole data values)          | `add_rational`, `mul_rational`, `print_rational` |
| **中层：表示层** | 实现有理数的算术逻辑 | **分子与分母** (Numerators & Denominators) | `rational` (构造函数), `numer`, `denom` (选择器)        |
| **底层：实现层** | 实现选择器和构造函数 | **具体数据结构** (如：两个元素的列表)                | 列表字面量 `[]`, 索引访问 `[0]`                           |
