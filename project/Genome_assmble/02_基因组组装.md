###### <font style="color:#df2a3f;">e.补完gap验证</font>
```bash
1. 近缘物种填入的 DNA 序列，能否被 P. zippeliana 自身的 HiFi 和 ONT reads 覆盖？
2. 有没有真实的长 reads 从 gap 左侧跨过填补区域，一直延伸到右侧？
3. 填入的序列是否与本物种 reads 一致，有没有异常错配、缺失或结构差异？
其中，第二个问题最重要，但三个问题需要结合评价。仅仅有 reads 比对到填补区域，不能证明 gap 一定填对了。
一、整个验证流程
最终 T2T 基因组 + 填 gap 前的基因组
确定哪些区域由近缘种序列填入

建立 reference-assisted gap BED 文件
记录每处填补区域在最终组装中的坐标

HiFi reads
评价序列一致性与较高精度的碱基支持

ONT reads
评价长片段连续性与跨越连接区域的支持



覆盖深度 + 两侧 junction + 完整跨越 + 错配检查


生成验证结果表
可以作为论文的 Supplementary Table

下面按你使用 Linux 服务器直接运行脚本的习惯来写。假设使用 16 个线程，后面都可以调整。
二、第一步：准备文件
建议建立一个独立目录：
mkdir -p Pz_gap_validation/{00input,01mapping,02coverage,03junction,04summary}
cd Pz_gap_validation


需要准备四类文件。
文件	示例文件名	用途
最终组装	Pz_final.fa	包含所有填补后的序列
HiFi 原始 reads	Pz_HiFi.fastq.gz	验证碱基准确性
ONT 原始 reads	Pz_ONT.fastq.gz	验证连续性
Gap 坐标	reference_filled_gaps.bed	指定近缘种填补的区域
前面三个文件你们应该已经有了。第四个 BED 文件需要从原始 gap-filling 记录或补 gap 前后组装中整理，不能直接根据最后的 T2T FASTA 猜测出来。
特别重要：怎么确定填补区域的坐标？
假设你原本有：
Chr01  ACGTACGTNNNNNNNNNNGCTAGCTA


使用近缘种补完后：
Chr01  ACGTACGTTGCAACCTAGGCTAGCTA


那么需要记录新插入片段 TGCAACCTAG 在最终序列中的准确位置。
BED 格式采用 0-based start、end-exclusive 坐标：
Chr01    1000000    1003500    gap001
Chr03    8500000    8512000    gap002
Chr08    16000000   16002500   gap003


这里的坐标只是格式示例，不是你基因组的真实 gap 位置。如果补 gap 过程中还发生了序列调整、删除或染色体重排，必须将原始坐标重新映射到最终版本。最好直接从 TGS-GapCloser 和人工补 gap 的日志、序列变更记录中获取位置。
这是整个验证最不能省略的一步。没有真实、准确的填补坐标，就不能可靠统计哪些 reads 支持近缘种序列。
三、第二步：将 HiFi 和 ONT reads 比对到最终基因组
这里建议使用 minimap2 + samtools。
首先建立最终基因组索引：
samtools faidx 00input/Pz_final.fa


假定四个输入文件都已经放进 00input 目录。
1. HiFi 比对
minimap2 \
    -t 16 \
    -ax map-hifi \
    00input/Pz_final.fa \
    00input/Pz_HiFi.fastq.gz \
    | samtools sort \
        -@ 8 \
        -m 2G \
        -o 01mapping/Pz_HiFi.sorted.bam -

samtools index -@ 8 \
    01mapping/Pz_HiFi.sorted.bam


map-hifi 是针对 PacBio HiFi reads 的预设参数。HiFi 数据准确度较高，适合检查填补区域是否存在碱基差异。
2. ONT 比对
minimap2 \
    -t 16 \
    -ax map-ont \
    00input/Pz_final.fa \
    00input/Pz_ONT.fastq.gz \
    | samtools sort \
        -@ 8 \
        -m 2G \
        -o 01mapping/Pz_ONT.sorted.bam -

samtools index -@ 8 \
    01mapping/Pz_ONT.sorted.bam


这里默认使用 map-ont，适合常见 ONT reads。若你的 ONT 数据为较新的高准确率 reads，也可以根据 minimap2 版本和测序数据类型评估其他预设。
注意，samtools sort 可能需要较多临时磁盘空间，所以建议检查工作目录的剩余空间。
3. 检查比对结果
运行：
samtools flagstat \
    01mapping/Pz_HiFi.sorted.bam \
    > 01mapping/Pz_HiFi.flagstat.txt

samtools flagstat \
    01mapping/Pz_ONT.sorted.bam \
    > 01mapping/Pz_ONT.flagstat.txt


查看：
cat 01mapping/Pz_HiFi.flagstat.txt
cat 01mapping/Pz_ONT.flagstat.txt


这一步主要检查 BAM 文件是否生成正常，以及整体比对情况。
需要提醒一点：整体比对率很高，不代表每一个填补区域都正确。 后面要针对 BED 中的每个 gap 单独验证。
四、第三步：统计每个填补区域的 reads 覆盖情况
假设你的真实坐标文件已经准备好：
00input/reference_filled_gaps.bed
首先排序：
sort -k1,1 -k2,2n \
    00input/reference_filled_gaps.bed \
    > 02coverage/gaps.sorted.bed


再分别统计 HiFi 与 ONT 在这些区域中的每个位点测序深度：
samtools depth \
    -aa \
    -Q 20 \
    -G 0x900 \
    -b 02coverage/gaps.sorted.bed \
    01mapping/Pz_HiFi.sorted.bam \

深度统计能回答每个 gap 内有多少位置得到 reads 支持。
建议最终计算这些指标：
指标	解释
Mean HiFi depth	HiFi 平均覆盖深度
HiFi breadth ≥1×	至少有 1 条 HiFi read 支持的碱基比例
HiFi breadth ≥5×	至少有 5 条 HiFi reads 支持的碱基比例
Mean ONT depth	ONT 平均覆盖深度
ONT breadth ≥1×	至少有 1 条 ONT read 覆盖的碱基比例

但不能简单把 5× 或 10× 当成通用合格阈值，因为还要考虑整个基因组的原始覆盖深度、重复性及比对质量。
五、第四步：检查 gap 两侧连接是否有 reads 跨越
这是比单纯 coverage 更关键的分析。
假设某个 gap 为：
不同类型的 reads 支持证据
示意图：只有 Read C 在同一连续比对区块中覆盖整个填补区域及其两侧锚定序列。Read A 和 Read B 分别支持一侧连接。
我们主要统计：
1. Left junction support：跨越 gap 左侧边界的 reads 数量。
2. Right junction support：跨越 gap 右侧边界的 reads 数量。
3. Full-span support：同一条 read 能够跨越整个填补区域及其两侧锚定序列的数量。
对于较长的填补区域，可能没有一条 read 能完整跨越，但可以分别验证左右边界以及内部序列。
需要注意：仅有一条 reads 的两个 supplementary alignments 分别落在 gap 两侧，不应直接计为可靠的连续跨越。
一个可直接使用的 Python 统计脚本
这个脚本使用 pysam，读取已有 BAM 文件及 gap BED 文件，统计每个区域的三个跨越指标。

conda install -c bioconda pysam


保存为 03junction/check_gap_junctions.py：
    for line in bed:        if not line.strip() or line.startswith("#"):            continue        fields = line.strip().split("\t")        chrom, start, end = fields[0], int(fields[1]), int(fields[2])        gap_id = fields[3] if len(fields) > 3 else f"{chrom}:{start}-{end}"        chrom_len = bam.get_reference_length(chrom)        # Require at least 'anchor' bp aligned on each side        left_start = start - args.anchor        right_end = end + args.anchor        left = set()        right = set()        full = set()        if left_start < 0 or right_end > chrom_len:            writer.writerow([                chrom, start, end, gap_id, end-start,                "NA", "NA", "NA"            ])            continue        for read in bam.fetch(chrom, left_start, right_end):            if read.is_unmapped:                continue            if read.is_secondary or read.is_supplementary:                continue            if read.is_duplicate or read.is_qcfail:                continue            if read.mapping_quality < args.mapq:                continue            name = read.query_name            if supports_interval(read, left_start, start + args.anchor):                left.add(name)            if supports_interval(read, end - args.anchor, right_end):                right.add(name)            if supports_interval(read, left_start, right_end):                full.add(name)        writer.writerow([            chrom, start, end, gap_id, end-start,            len(left), len(right), len(full)        ])bam.close()

另外，脚本里的 --anchor 1000 表示跨越边界时要求两侧各至少 1 kb 的连续比对。对于非常短的 gap，这个要求比较严格；对于长重复序列，1 kb 又可能不够保证唯一性，应该结合局部重复注释调整。
六、第五步：进一步检查填补序列是否准确
前面三步验证的是 reads 覆盖及序列连接，但你们使用近缘种填入 DNA，因此还需要确认：
近缘种序列是否与 P. zippeliana 自身真实序列一致？
例如：
Reference-filled:  ACGTACCTGATCCGTA
P. zippeliana:    ACGTATCTGATCCGTA
                       ^
                    序列差异


即使 reads 完整跨越了 gap，也可能存在 SNP、indel 或局部重复拷贝差异。
建议首先用 IGV 检查：
- HiFi reads 是否在填补区域集中出现一致的 mismatch。
- 是否存在大量 reads 支持同一个 insertion/deletion。
- gap 内外的覆盖深度是否发生明显变化。
- ONT reads 是否出现大规模 soft clipping 或异常分段比对。
- 是否有 reads 明显支持与最终组装不同的序列结构。
对于出现疑似错误的区域，可以使用 HiFi reads 进行局部变异检测或重新组装，并与最终参考填补序列比较。
这里需要注意，你研究的是四倍体，所以不能把每个变异都当作组装错误。某些变异可能来自真实的等位差异或 homoeologous reads 的错误比对。需要根据亚基因组特异序列、比对唯一性和等位比例进一步判断。
七、最终建议生成什么结果表？
建议为论文补充一张类似这样的 Supplementary Table：
Table Sxx. Validation of reference-assisted gap-filled regions in the Prunus zippeliana genome assembly.
Metric	内容
Gap ID	gap 编号
Chromosome	染色体
Start / End	最终组装中的坐标
Filled length (bp)	实际填入长度
Reference species	提供填补序列的近缘物种
HiFi mean depth	HiFi 平均深度
HiFi coverage (%)	HiFi 覆盖比例
ONT mean depth	ONT 平均深度
ONT coverage (%)	ONT 覆盖比例
HiFi spanning reads	HiFi 完整跨越 reads 数
ONT spanning reads	ONT 完整跨越 reads 数
Junction support	两侧连接证据
Sequence concordance	序列一致性评价
Validation status	Supported / Uncertain / Unsupported
验证后根据结果分类，不建议简单规定“超过 5 条 reads 就合格”。尤其在重复区域中，多条 reads 可能都来自错误匹配的同源拷贝。
八、验证完成后，论文怎么写？
假如验证结果显示参考辅助填补区域都得到了可靠支持，可以在 Methods 原有第 154–157 行之后增加：
To assess the reliability of reference-assisted gap filling, PacBio HiFi and ONT reads from P. zippeliana were independently aligned to the final genome assembly using minimap2. Read coverage, alignment consistency and support for both junctions of each gap-filled region were examined. Long reads spanning the filled regions and their flanking sequences were further assessed to identify potential assembly errors. The validation results are summarized in Table Sxx.




这段表达比较自然，适合基因组论文，也不会过度声称所有 gap 都已经完全验证。不过，必须在相应检查实际完成后再使用。
如果验证中发现不能确认的区域，应明确报告，并优先用本物种 reads 重新解析。不能把参考辅助填补后的无 N 序列，直接等同于真实完成的 T2T 序列。
```
