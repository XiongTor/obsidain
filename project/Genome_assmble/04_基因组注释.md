```bash
直接用 Helixer 预测基因，可以得到比较高质量的 ab initio 注释；但 Helixer 毕竟没有利用你的转录组/蛋白证据。
通常推荐的做法是 “evidence-based + ab initio 整合”，也就是你说的 Liftoff + Helixer 整合。

一个常见的工作流程（Prunus 这种有近缘参考基因组的情况）
1. Liftoff（参考基因组注释迁移）

输入：

你的基因组 padus.fna

一个高质量近缘物种（比如 Prunus avium, Prunus persica）的 GFF/GTF 注释

输出：

padus_liftoff.gff3（迁移后的注释，尽量保留真实基因结构）

命令示例：

liftoff padus.fna reference_genome.fna reference.gff3 -o padus_liftoff.gff3 -u unmapped.txt -p 20

2. Helixer（深度学习 ab initio 预测）

helixer predict --fasta padus.fna --species arabidopsis --outdir helixer_out

（这里的 --species 是 Helixer 的模型标签，不一定要是 Prunus，因为模型训练集有限，常用 arabidopsis 或 generic）

3. 整合注释（EVM 或 Maker）

EvidenceModeler (EVM)：专门用于合并多种证据（protein/CDNA alignment、ab initio 预测、liftoff 注释）。
MAKER：比较完整的 annotation pipeline，可以结合 Liftoff 注释 + Helixer ab initio + RNA-seq/蛋白证据。

核心思想：
给不同来源的注释设置权重，例如：
Liftoff（参考迁移，保守）→ 权重高
RNA-seq 或 protein evidence（可靠性高）→ 权重高
Helixer（ab initio）→ 权重次之
然后整合成一个统一的 GFF3。

4. 质量评估
用 BUSCO 检查注释的 completeness。
比较 Liftoff-only、Helixer-only、整合后的 BUSCO 完整度，通常 整合结果最好。
如果你有 RNA-seq，可以用 BRAKER2 或 StringTie + PASA 来进一步修正基因结构。
推荐组合方案（对你这个 Prunus padus）
Liftoff 从 P. persica 或 P. avium 注释迁移（获得比较保守的 annotation）。
Helixer 做 ab initio，补充缺失基因。
EVM 整合二者，RNA-seq 如果有也加进去。
最后用 BUSCO 和 InterProScan 评估。

project/
 ├── genome/
 │    ├── padus.genome.fna
 │    └── padus.repeatmasked.fna   # 如果做了repeatmask
 ├── annotation/
 │    ├── liftoff/

 │    ├── evm/
 ├── config/
 │    └── config.sh
 └── run_annotation.sh

config/config.sh
#!/bin/bash

# 基因组
GENOME=genome/padus.genome.fna

# Liftoff参考注释 (比如近缘种的gff3)
REF_GFF=reference/prunus_persica.gff3
REF_GENOME=reference/prunus_persica.fna

# Liftoff参数
LIFTOFF_THREADS=20

# Helixer参数
HELIXER_THREADS=4

# EVM权重设置
# 数字越大代表权重越高，这里假设 Liftoff(4) > Helixer(2)
EVM_WEIGHTS="Liftoff,4 Helixer,2"

run_annotation.sh
#!/bin/bash
set -euo pipefail

source config/config.sh

mkdir -p annotation/liftoff annotation/helixer annotation/evm

# -----------------------------
# Step 1: Liftoff
# -----------------------------
echo "[`date`] Running Liftoff..."
liftoff -g ${REF_GFF} -p ${LIFTOFF_THREADS} \
        -dir annotation/liftoff \
        -o annotation/liftoff/liftoff.gff3 \
        ${GENOME} ${REF_GENOME}

# -----------------------------
# Step 2: Helixer
# -----------------------------
echo "[`date`] Running Helixer..."
helixer predict \
    --fasta ${GENOME} \
    --species generic \
    --out annotation/helixer/padus_helixer.gff \
    --cpu ${HELIXER_THREADS}

# -----------------------------
# Step 3: Evidence Modeler (EVM)
# -----------------------------
echo "[`date`] Preparing EVM input..."

mkdir -p annotation/evm/inputs
cp annotation/liftoff/liftoff.gff3 annotation/evm/inputs/liftoff.gff3
cp annotation/helixer/padus_helixer.gff annotation/evm/inputs/helixer.gff3

# 转换 GFF3 为 GTF
gffread annotation/evm/inputs/liftoff.gff3 -T -o annotation/evm/inputs/liftoff.gtf
gffread annotation/evm/inputs/helixer.gff3 -T -o annotation/evm/inputs/helixer.gtf

# 创建权重文件
cat > annotation/evm/weights.txt <<EOF
Liftoff   gene    4
Liftoff   exon    4
Helixer   gene    2
Helixer   exon    2
EOF

echo "[`date`] Running EVM..."
evm.py \
    --genome ${GENOME} \
    --weights annotation/evm/weights.txt \
    --gene_predictions annotation/evm/inputs/liftoff.gtf,annotation/evm/inputs/helixer.gtf \
    --output_file annotation/evm/evm.gff3 \
    --output_format gff3

# -----------------------------
# Step 4: 提取 CDS 和 Protein
# -----------------------------
echo "[`date`] Extracting CDS and protein sequences..."

gffread annotation/evm/evm.gff3 \
    -g ${GENOME} \
    -x annotation/evm/evm.cds.fasta \
    -y annotation/evm/evm.protein.fasta

echo "[`date`] All done!"
echo "Final files:"
echo " - annotation/evm/evm.gff3 (final annotation)"
echo " - annotation/evm/evm.cds.fasta (CDS sequences)"
echo " - annotation/evm/evm.protein.fasta (protein sequences)"

输出结果
annotation/evm/evm.gff3 → 最终的整合注释
annotation/evm/evm.cds.fasta → CDS 序列
annotation/evm/evm.protein.fasta → 蛋白序列
```

```bash
# intron_stats.py
import gffutils
import sys

gff_file = sys.argv[1]
db = gffutils.create_db(gff_file, dbfn=':memory:', force=True, keep_order=True, merge_strategy='merge', sort_attribute_values=True)

total_introns = 0
sum_intron_length = 0

for mrna in db.features_of_type('mRNA'):
    exons = list(db.children(mrna, featuretype='exon', order_by='start'))
    # 先排序
    exons.sort(key=lambda x: x.start)
    intron_count = max(0, len(exons)-1)
    total_introns += intron_count
    for i in range(len(exons)-1):
        intron_len = exons[i+1].start - exons[i].end -1
        if intron_len>0:
            sum_intron_length += intron_len

avg_intron_length = sum_intron_length / total_introns if total_introns>0 else 0
print(f"Intron_count={total_introns}")
print(f"Average_intron_length={avg_intron_length:.2f}")
```

###### c. PSAURON：基因组注释质量精准评估工具PSAURON
随着基因组测序技术的快速发展，精准的基因注释已成为生物学研究的关键环节。然而，传统注释质量评估工具存在明显局限：BUSCO主要评估注释完整性，但没法判断注释的序列是不是“真的”编码基因；QUAST关注组装质量，对注释的精确性无能为力；OMArk依赖同源蛋白信息，无法直接评估注释的精确性。PSAURON的推出，填补了这一重要空白。

参考链接：[https://mp.weixin.qq.com/s/PQx2e932wG8p31hmeWW8PQ?click_id=16](https://mp.weixin.qq.com/s/PQx2e932wG8p31hmeWW8PQ?click_id=16)



**环境配置与安装**

PSAURON可通过pip直接安装，建议使用conda安装：

conda create -n psauron -y

conda activate psauron

conda install psauron -y

**输入文件准备**

支持两种输入格式：

+ **CDS****序列**（推荐）：使用gffread从GTF/GFF文件提取
+ **蛋白质序列**：直接提供氨基酸FASTA文件（<font style="color:#ee0000;">需加-p参数</font>）

输入的CDS 序列需满足：无框内终止密码子、起始密码子标准、仅含 ACGT 核苷酸，长度能被 3 整除（工具会自动过滤不符合的序列，但提前处理能提高效率）。



**参数配置详解**

主要参数包括：

+ -i/--input-fasta：输入FASTA文件路径（必需）
+ -o/--output-path：输出文件路径（默认./psauron_score.csv）
+ -m/--minimum-length：最小蛋白长度（默认5个氨基酸）
+ -e/--exclude：排除包含特定关键词的序列
+ --inframe：框内分数阈值（默认0.5），取值范围 [0, 1]；数值越大越保守（高特异性，低灵敏度）
+ --outframe：框外分数阈值（默认0.5），取值范围 [0, 1]；数值越大越宽松（高灵敏度，低特异性）
+ -c/--use-cpu：强制使用CPU
+ -s/--single-frame：仅评估注释阅读框
+ -p/--protein：输入为蛋白质序列
